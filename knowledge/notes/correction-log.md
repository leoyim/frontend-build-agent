# 纠错记录

典型误区、修正原因与最终理解。

> 本文件收录三类纠错：① 学习过程中的**认知偏差**（含其具体表现形式）；② 具体知识点上的**错误结论**及其修正；③ 课程中出现的**事实性错误**及其更正。
>
> 收录标准：**有复用价值**。一次性的口误、与知识无关的表述问题不收录。

---

## 一、认知偏差（比知识点更值得修正的部分）

以下七类偏差由三天的作答记录归纳而来。它们不是"某个知识点不会"，而是**思考动作的顺序错了** —— 因此修正方式是**换动作顺序**，不是补知识。

### 偏差 1 · 把「结果」当「原因」

| 项 | 内容 |
|---|---|
| **表现** | 结论答对了，但说不出机制。例如能说出"Loader 从右到左执行"，但被追问为什么时答不上来 |
| **修正原因** | 记住的是**结论**，不是**因果链**。结论会在换工具时失效，因果链不会 |
| **修正动作** | 追一层「为什么」。判据：**这句话能推出反例吗？** 推不出反例的，多半是记住的结论而非理解的机制 |
| **最终理解** | Loader 顺序不是"规定"，是**类型转换管道**的必然结果 —— 每一步的输出必须匹配下一步的输入。喂错类型管道就断 |

### 偏差 2 · 层级判反

| 项 | 内容 |
|---|---|
| **表现** | 把「注入 style 标签」判成 Plugin，把「生成 manifest」判成 Loader |
| **修正原因** | 用**流程动作**做判断依据（"这个动作看着像在流程里"），而不是用**作用域** |
| **修正动作** | 回到作用域判别：**单文件内容 → Loader；跨文件 / 构建阶段 / 产物编排 → Plugin** |
| **最终理解** | 判别标准是**"它处理的是谁"**，不是**"它看起来在干什么"** |

### 偏差 3 · 混淆「自己的配置」与「第三方库的字段」

| 项 | 内容 |
|---|---|
| **表现** | 被问"怎么减小第三方库的体积"时，答"在我项目的 `package.json` 里配 `sideEffects`" |
| **修正原因** | 把**自己的项目**当成了**第三方库**。`sideEffects` 是**库作者**写的字段，消费方改了没用 |
| **修正动作** | 每次先问一句：**这是谁的配置？** |
| **最终理解** | 消费方能控制的是**导入路径**（`lodash-es/debounce`），不是库自己的字段。这就是"最狠的一招是改导入方式"的由来 |

### 偏差 4 · 机制链条不串联

| 项 | 内容 |
|---|---|
| **表现** | 一被追问「为什么」，就归因到「工具支持不支持」这类**表象**，没有挂回已学过的底层机制 |
| **修正原因** | 知识点之间是**孤岛**，没有连成链 |
| **修正动作** | 要求答案包含「因为…所以…」的完整链条，且链条末端必须落在一个**已学过的底层机制**上 |
| **最终理解** | 「工具支持不支持」是**现象**；「构建期字面量替换 + 死代码删除」才是**机制**。同一个现象在 Rspack / Rolldown / Turbopack 里各有实现，机制只有一个 |

### 偏差 5 · 解决问题顺序错位

| 项 | 内容 |
|---|---|
| **表现** | 遇到"缺失某个 loader"，直接跳到"自己写一个 Vite 插件" —— 而这是**成本最高**的一条路 |
| **修正原因** | **跳过必要的分解步骤**：没先问"有没有现成的"，直接进到"怎么实现" |
| **修正动作** | 规则化顺序：**先替代 → 再复用 → 最后自写** |
| **最终理解** | 这个顺序在别处同样成立。装插件前先问「默认值够不够」，迁工具前先问「有没有真实痛点」—— 都是同一个动作 |

### 偏差 6 · 复用现成答案，不针对新场景拆解

| 项 | 内容 |
|---|---|
| **表现** | 被问"组件库该不该用 Vite"，把讲述"全新应用"那一行的理由（冷启动快、生态成熟）搬了过来 —— 而组件库在 CI 里跑 build，**根本没有 dev server** |
| **修正原因** | 拿**上一个场景的答案**回答新场景，没有先确认两个场景的差异 |
| **修正动作** | 回答前先问：**这个场景和上一个场景，哪里不一样？** |
| **最终理解** | 组件库的真实需求是：产物格式（ESM + CJS）、类型声明（`.d.ts`）、外部依赖不打包（`external` peer）、`package.json` 入口字段对齐。与"冷启动快不快"几乎无关 |

### 偏差 7 · 以例代概念 / 答「是什么」代替答「怎么做」

| 项 | 内容 |
|---|---|
| **表现** | 三次连续复现 ——「新老并济」（用口号代替机制）、「生态优势」+「TurboPack」（用标签 + 案例代替命名）、用工具清单代替分类 |
| **修正原因** | 用**实例或短语**指代**原则**，导致答案无法复用、无法证伪 |
| **修正动作** | ① 回答**抽象问题** → **先命名概念，再举例**；② 回答**分类问题** → **先给类别名，再列实例**；③ 回答**排序 / 动作问题** → **先问痛点在哪**，再谈难度 |
| **最终理解** | 「新老并济」的正确表述是 **dev / prod 一致性（parity）** —— 统一引擎后，"本地能跑、生产挂"这一**整类** bug 消失。命名之后，这句话才**可以证伪**（问：那 HMR 速度变快了吗？答案是不能，收益不在 dev） |

### ⭐ 一个正向转折（记录以固化）

在被告知「换 Rspack 后构建从 90 秒降到 12 秒」时，学习者**首次主动反问**：「你说的是哪个阶段？dev 还是 build？你的项目有多大？」

这标志着跨模块习惯（**拆指标 → 查前提 → 自己测**）真正装上。此前遇到笼统数字时，他的反应是接受对方给的框架去讨论。

**仍未完成的一问**：还差「**怎么测的**」（跑几次、清缓存没、取中位数没）。

## 二、知识点误区与修正

| # | 误区 | 修正后的认知 | 章节 |
|---|---|---|---|
| 1 | 以为共享模块在产物里也会去重 | 图去重只管**内存**；产物是否重复由 `splitChunks` 决定 | §2.1 |
| 2 | 把"抽公共包"当打包器默认行为 | Webpack 5 默认 `chunks: 'async'`，只处理动态 import | §2.2 |
| 3 | 以为 loader 顺序错了"所以报错" | 本质是**类型管道**，喂错类型才断 | §2.3 |
| 4 | 以为「Vite dev 依赖预构建只是为了性能」 | 首要理由是 **CJS/UMD → ESM 兼容**；不做则直接跑不起来 | §3.2 |
| 5 | 把"600+ 请求"叫**请求瀑布** | 那是并发风暴导致的**网络拥塞**；瀑布指**串行依赖链** | §3.2 |
| 6 | 以为「Vite 冷启动快」=「首屏快」 | 成本被**挪到首次访问**；且不影响生产 | §3.1 |
| 7 | 说"Webpack 什么都要手配" | Webpack 有默认值，只是只覆盖**骨架层** | §3.3 |
| 8 | 说"Vite 不支持 `process.env`" | **浏览器没有 `process`**；Webpack 靠构建期替换伪造 | §3.4 |
| 9 | 动态取 `import.meta.env[k]` | 静态替换只能替换**完整字面量表达式** | §3.4 |
| 10 | 以为 Rollup 插件拿来就能用 | dev 不打包，`generateBundle` 等钩子**不触发** | §3.5 |
| 11 | 说"Vite 构建更快" | build 走 Rollup **单线程**，超大项目可能更慢 | §3.6 |
| 12 | 选型先算 ROI | 应先问**有没有真实痛点**；无痛点则收益侧为空 | §7.5 |
| 13 | 组件库直接用 Vite 默认配置 | 需 dts 插件、显式 `formats`、`external` peer、对齐 `exports` | §7.5 |
| 14 | 以为 esbuild / SWC 能做类型检查 | 只**剥离类型标注**，不验证类型 | §4.2 |
| 15 | 以为 `vite build` 会因类型错误失败 | **默认不会**，需显式挂 `tsc --noEmit` | §4.2 |
| 16 | 以为 SWC 能完全替代 Babel | 插件体系不同（Rust/WASM vs JS），**搬不过去** | §4.2 |
| 17 | 以为"兼容"等于 100% 无痛迁移 | Rspack 是"几乎全部 loader + top 50 插件 >80%" | §4.3 |
| 18 | 以为另造生态只是"成本高" | 是**冷启动起不来**（双边网络效应） | §4.3 |
| 19 | 以为 Turbopack 可以通用 | **框架内置**，离开 Next.js 无意义 | §4.4 |
| 20 | 以为 Turbopack **"没有替代品"** | 仍可显式 `--webpack` 退回。**强制 = 默认 + 高摩擦回退**，不是禁止 | §4.4 |
| 21 | 以为 Vite 8 的收益在 dev | **HMR 相比 Vite 7 基本没变**，收益在生产构建与依赖预构建 | §4.4 |
| 22 | 以为换引擎只是"变快" | 产物结构与体积是**另一回事**，必须回归对比 | §4.5 |
| 23 | 按"谁最新"决定学什么 | 判据是**折旧率 + 是否在默认路径 + 兼容对象** | §4.5 |
| 24 | 把原始 build log 整个塞给 AI | 一次几万 token，应转**结构化诊断** | §6.3 |
| 25 | 以为 AI 看得见浏览器 | DOM / console 在**运行时**，源码里没有 | §6.3 |
| 26 | 按工具换代排学习顺序 | **按能力排**，配置只学一遍 | §7.1 |
| 27 | 把"能跑起来"当学会了 | 判据是「**你能预测什么**」 | §7.2 |
| 28 | 没有判据就动手 | **先写判据，再动手** | §7.3 |
| 29 | 台阶 4 只跑一次基准 | 单次测的是**系统负载**，不是构建性能 | §5.6 |
| 30 | 写了"能迁"就收工 | 没有**回退路径**的是假报告 | §7.6 |
| 31 | 想"把文档读完" | 文档是**字典**，不是教材 | §7.4 |
| 32 | 从 `index.js` 漫读源码 | **先有问题，再读源码** | §7.4 |
| 33 | 读完源码不留可验证结论 | 写不下「我验证了 X 是 Y」= 没读 | §7.4 |

## 三、被更正的事实性错误

| # | 曾出现的错误说法 | 更正 | 性质 |
|---|---|---|---|
| 1 | 「Turbopack 没有其他可替代的工具」 | Next.js 16 保留显式 `--webpack` 退回。真实机制是**默认即权力** —— 不是禁止回退，而是把回退做成"逆默认值"操作，大多数团队不会去按 | 事实精度偏移 |
| 2 | 「Terser 是单线程，所以换 SWC minify 才快」 | Webpack 5 里 Terser 默认 `parallel: true`（worker 线程），**并非纯单线程**。换 SWC minify 的收益来自 ① 原生执行速度 ② 更低的序列化 / 内存开销 | 精度不足 |
| 3 | 「Rspack 兼容 Webpack 是 ROI 划算」 | 不是 ROI 选择，是**生存条件**。缺的是双边网络效应这条机制 | 归因层级过低 |
| 4 | 「Webpack 的静态资源处理需要配 loader」 | Webpack 5 的 asset modules 官方表述是 "without configuring additional loaders"，但仍需一行 `type: 'asset/resource'`。**精度上要说"已内置，但需一行规则声明"** | 表述不精确 |
| 5 | 把「第 2、5 节均已批改、只是没确认」当成缺口描述 | 模块 3 §2 实际**从未作答**，既没答也没批改。**"已批改"与"未作答"是两种不同状态**，不能合并描述 | 状态描述失真 |

> **第 5 条的通用教训**：它与「速度数字必须绑定指标」是同一类错误 —— **状态和数字都必须绑定可判定的定义**，否则会失真而不自知。

## 四、一条关于「出题」的教训（对自学者同样适用）

课程中出现过一次**题目失效**：讲解的表格里已经写出了答案，紧接着用同一内容出题 —— 学习者只需**检索**，无需**产出**，题目失去检验价值。

由此得出的规则：

| 规则 | 原因 |
|---|---|
| **答案不得与题目同屏** | 同屏即退化为检索题 |
| 题目必须要求**产出**，不是**检索** | "你会怎么改造"要求判断与取舍；"上表第几行说了什么"只考记忆 |
| 抽象题要有**具体场景外壳** | 不问"什么是 parity"，问"合并引擎后最值钱的收益是什么，为什么不是速度" |
| 允许并要求**跨节回环** | 好题让人把本节结论挂回前面学过的机制 |

**自学者应用**：给自己出复述题时，先合上讲义再答。看着原文回答，测的是眼睛，不是脑子。
